# Sonora audit — 2026-11-11

Ran on `emulator-5554` (1080×2424, 411dp and 360dp), debug build of `bd76dac`.
Unit tests pass (`./gradlew :app:testDebugUnitTest`).

Flows exercised: launch, Home scroll, Search (query, YouTube/Soulseek toggle, top result),
play, mini player, Now Playing, Queue, Library (Tracks/Albums), artist page, track actions sheet,
Settings, Taste, Network, signed-out download prompt.

Severity: **Blocker** = a flow is dead or unreadable · **High** = wrong result or a missing state ·
**Medium** = inconsistency or weak affordance · **Nit** = polish.

---

## Blocker

**B1. Soulseek search with no session is a blank black page.**
`SearchScreen.kt:491` renders rows only `if (searchState.hits.isNotEmpty())` — no else branch, and
`statusNote` returns null when there are no hits. Tapping **Soulseek** before signing in leaves the
whole content area empty: no message, no button, nothing that says why.
Fix: an empty state in that branch — "No peer results yet", plus **Sign in to search the network**
when `state !is Connected`, wired to the existing `onNeedPeers`.

**B2. The Search → artist/album transition is a tab switch, and back does not return.**
`SonoraApp.kt:464-483` sets `tab = MainTab.Library` in both `onOpenAlbum` and `onOpenArtist` when a
result is tapped in search. On device: Search → tap *Billie Eilish* → the Library tab lights up → system
back lands on the Library root. The query, the results and the tab the user was in are all gone.
Fix: push the page onto `searchPages` (`ShelfPage`) when the tab is Search, or keep a
"return to Search" entry in Library's back handler.

## High

**H1. Library → Albums and Artists show a placeholder note for every streamed album.**
`LibraryScreen.kt:602` (`AlbumRow`) and `:633` (`ArtistsSection`) pass
`artworkFile = album.tracks.firstOrNull()?.file`. A track streamed from YouTube Music has `file ==
null`, so every album made of streams draws the generic music note — while the same albums show real
covers on Home and in the Tracks list. In a YouTube-first app this is the default state of the tab.
Fix: fall back to `rememberTrackArtwork(firstTrack, px = CARD_ART_PX)` when `file == null`.

**H2. Swipe-to-queue cannot ever fire, and nothing calls it.**
`SongRow.kt:296-308`: `onHorizontalDrag` sets `fired = true` on every pixel of movement, so
`onDragEnd`'s `!fired` is always false; `width` is declared `1f` and never measured, so the
threshold is 0.45px. Separately, a grep for `onSwipeToQueue` finds no caller anywhere in the app.
The reveal background and the gesture are both unreachable.
Fix: delete `swipeable`, `QueueSwipeBackground` and the `onSwipeToQueue` parameter — or fix the flag
and measure the row width, then wire it into the search and library rows.

**H3. The Taste screen has no visible way back.**
`SonoraApp.kt:716` draws `TasteScreen` as a full-screen overlay with only a system `BackHandler`.
Every other sub-page (artist, album, playlist) carries a back button; this one has none, and the tab
bar and mini player are not drawn over it either.

**H4. Read-only rows draw a chevron that goes nowhere.**
`SettingsRows.kt:187` draws `KeyboardArrowRight` when `value != null || onClick != null`, so
*Tracks learned*, *Plays recorded*, *Likes folded in*, *Last updated*, *Top artists*, *Top tags* and
*Strongest transitions* all show a navigation affordance and are not clickable.
Fix: chevron only when `onClick != null`.

**H5. The artist page's track list has no heading.**
`ArtistDetailScreen` draws the "Albums and singles" shelf and then the track rows directly below,
with no "Songs"/"Popular" label. The list reads as a continuation of the albums row.

**H6. Three touch targets are below the 48dp minimum.**
| Control | Size | Where |
|---|---|---|
| Row overflow (⋮) | 36dp | `SongRow.kt:213` |
| Mini player transport | 40dp | `MiniPlayer.kt:60` |
| Cancel download | 32dp | `HomeScreen.kt:415` |

Raise to 48dp with padding (the glyph can stay the same size).

**H7. Category tiles show two names for the same thing.**
The grid borrows YouTube Music's cover, which already has its own headline ("GAMING HITS",
"Lofi Loft", "Classical for Sleeping", "Bollywood Melancholy"), and then prints our label on top
("Gaming", "Focus", "Sleep", "Sad"). On *Gaming* and *Sad* the two texts are directly on top of each
other. Fix: crop the tile to the upper part of the cover, or drop our label where the cover already
carries text.

**H8. Home and Search end in the same content.**
`HomeScreen.kt:211` and `SearchScreen.kt:334` both render `BrowseShelves` — the same Browse all grid
and the same category shelf. Two of five primary tabs open onto a catalogue grid. Home's own doc
comment says it is "what's new and what's next", not a browse page.
Fix: keep the grid in Search; Home keeps Recently added / Recently played / Playlists / Keep looking.

**H9. A category with no cover renders as an empty grey box.**
The *Diwali* tile is a flat grey rectangle: `gradientFor(tint)` produces grey when the category's
stripe colour is grey or missing, and there is no image. Every other tile has depth.
Fix: fall back to the note glyph or the category's initial when the gradient is achromatic.

## Medium

**M1. Queue panel.** `QueuePanel.kt` — "Autoplay: on" is a centred bold sentence that is actually a
toggle and does not look tappable; the counter "5" beside *UP NEXT* has no unit ("5 tracks");
the tag **AUTOPLAY** is repeated under all five rows. Move autoplay to a switch row in the header,
give the count a noun, and mark the autoplay boundary once.

**M2. Now Playing.** The volume slider (`DeviceVolume.kt`) duplicates the hardware volume keys and
takes a full row; the bottom row of four unlabelled icons (lyrics, shuffle, repeat, queue) has no
grouping; the **YT Music** badge is 12% white on 12% white (low contrast). Shuffle/repeat also have
no visible on-state in the default position.

**M3. Mini player.** No progress line, and the swipe-left/right-to-skip gesture has no affordance.
The play glyph is accent red while its neighbours are white, so the middle control reads as a
different kind of control rather than the same row.

**M4. Search.** *Play* and *Playlist* are two outlined pills of equal weight — Play is the primary
action and has no primary treatment. "From YouTube Music; tap to open" is printed under both Artists
and Albums; "Artist" is printed under every artist name in a section already called Artists.

**M5. Metadata order is inconsistent.** Library rows read `artist · album`
(`SongRow.kt:77`); the artist page passes `album · artist`. Pick one.

**M6. Recently played at 360dp.** The recents shelf pages sideways in columns
(`HomeScreen.kt:238`); at 360dp the next column shows two 52dp cover slivers at the right edge with
no text, which reads as a rendering glitch.

**M7. Settings has no About row** — no version, no licence, no source link, on an AGPL app. There is
also no search across settings.

**M8. Empty-ish pages.** With four tracks the Library is 75% black. Empty states exist for the
sub-tabs but not for a Library that is merely small.

**M9. Section headings are cut in half by the floating bar.** The bottom scrim is drawn around the
bar; a heading entering the viewport is clipped mid-glyph (Home, Search, Settings all showed this).

**M10. Position polling.** `SonoraApp.kt:407` polls `syncPosition()` every 500 ms for as long as a
track is loaded, which recomposes the player subtree twice a second. Media3 already emits position
updates; drive the bar from a `StateFlow` instead.

## Nit

- Field corner radius is 11dp (`Bits.kt:216`, `:294`) but the Connect button is 13dp
  (`SonoraApp.kt:301`).
- `HomeScreen.GettingStarted` (`:444`) is defined and never called.
- "Unknown album · Various artists · 4 tracks" appears as a real album row — the fallback bucket is
  presented as content.
- `ResultSectionHeader` uses `titleSmall`, which is not in the custom type scale, so it falls back
  to Material's default weight.

---

## What already works — keep it

- The frosted mini player and tab bar sampling one `HazeState`, so both blur the same frame.
- The tab bar's deforming selection indicator and the 2.35:1 hero card shape — both are deliberate
  and read as such.
- The two-accent-token colour scheme (`Accent` for surfaces, `AccentText` for ink) with contrast
  worked out in the comments.
- The artwork-derived backdrop on the player and detail pages, and the shared `SongRow` across every
  list.
- The signed-out *Connect to the network* sheet: it explains *why* before asking, and offers
  "Not now".

---

## Suggested fix order

1. B1, B2 — a blank page and a lost back stack.
2. H1, H4, H6 — artwork, false affordances, touch targets.
3. H3, H5, H7, H9 — the missing back button and the two-label tiles.
4. H2 — decide: delete the swipe, or finish it.
5. H8 — decide what Home is for.
6. Medium, then nits.
